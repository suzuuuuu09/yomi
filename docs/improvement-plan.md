# 改修方針

## 合意済みの対象と順序

利用者への不具合を先に修正し、その後に未使用コード・重複処理・不要な状態管理を整理する。
コードとドキュメントを対象とし、現行の機能仕様は [requirements.md](./requirements.md) を参照する。

既存HTTP APIのURL・入力・応答形式は維持する。アーカイブ用の両URLも残し、整理は内部の共通化で行う。

## 修正対象

- 書誌編集と進捗更新が競合しても、ページ数・読書状態・読了日の整合性を保つ。
- 本・メモは保存成功後に表示し、保存失敗時は下書きを残す。
- 再取得の古い応答で新しい状態を上書きせず、再取得失敗を画面に残す。
- 操作用カードをキーボードでも使えるようにし、ジャイロの許可判定を一本化する。
- 編集フォームは開くたびに保存済みの値から始める。

## 検証

HTTP API、ストア操作、ボタンの出力HTMLを回帰テストの対象とする。
SQL条件と制約は、リポジトリのマイグレーションを適用したインメモリSQLiteで実行する。D1の実行境界はテスト用に置き換えるため、本番D1や実機の検証とは区別する。
