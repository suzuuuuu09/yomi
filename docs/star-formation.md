# 要件・設計メモ

## 星の配置ロジック

API（Hono / Cloudflare Workers）が座標・明るさ・色を計算してDBに保存する。星座線は一覧取得時にAPIで計算し、クライアントも書籍更新時に同じ関数で再計算する。
実装は `src/server/lib/star-formation.ts`、呼び出し元は `src/server/routes/books.ts` と `src/store/useLibraryStore.ts`。

### 座標の決め方

ジャンル別クラスタリングを採用する。ジャンルごとに3D空間の「星雲の中心」を固定し、同ジャンルの星が同じ領域に集まることで、ジャンル単位の「星座クラスター」を自然に形成する。

- ジャンルごとに中心座標 `(cx, cy, cz)` を決定論的に割り当てる（ジャンル文字列のハッシュから導出）
- 新しい星は中心から `±1.5` のランダム散布で配置
- 同じユーザーの既存の星（アーカイブ済みを含む）との距離が `< 1.0` なら再試行する。試行は最大10回で、最後の候補は距離にかかわらず採用するため、重なりの回避は保証しない
- ジャンル未指定の中心は `[0, 0, 0]`
- 本の登録時にAPIが座標を計算してDBに保存する。ジャンル編集時は座標を移動しない

### 色の決め方

ジャンル文字列から色相（Hue）を決定論的に固定し、読書進捗（brightness）で明度を変化させる。

- `genre → H`：ジャンル文字列のハッシュ値×360を四捨五入して色相を算出（同ジャンルは常に同系色）。ジャンル未指定は `240`
- `S`（彩度）: 固定 `70%`
- `brightness = 0.15 + min(currentPage / totalPages, 1) × 0.75`。総ページ数が0なら `0.15`
- `L`（明度）: `round(35 + brightness × 40)`。未読は `41%`、読了は `71%`
- 出力は `hsl(H, 70%, L%)` 形式の文字列
- 本の登録・進捗更新・書誌情報の編集時にAPIが再計算してDBに保存する
- 画面上の星の大きさ・発光・またたきは、フロントの `starVisuals` と `UniverseCanvas` が進捗・状態に応じて別途計算する

### 星座の線を引く条件

「読了を星座の確定として演出」「ジャンルのメタデータで知識の関連性を線で結ぶ」というコンセプトに基づき、以下の3条件をすべて満たすペアに線を引く。

```
1. 両方の status === "completed"
2. 同じ空でない genre
3. 3D距離 < 4.0
```

- `GET /api/books` がアーカイブされていない本から `constellationLines: [string, string][]` を計算して返す
- 進捗更新APIは更新後の `book` を返す。クライアントは書籍の追加・編集・進捗更新・アーカイブ・復元などで同じ計算関数を使い、星座線を更新する
- 描画時は現在表示している両端の本が存在する線だけを3D空間に描く
