# ゲストモードの検討

2026年10月30日、全体の方針を利用者が確認し、検討結果として確定した。その後の実装依頼に基づき、下記の方針を実装する。

## 合意した範囲

- ログインせずに利用でき、本と読書記録をブラウザー内に保存する。
- ネット接続を前提とし、オフラインでの起動は保証しない。
- ログイン後に、ゲストデータをアカウントへ引き継ぐか選べるようにする。自動では転送しない。
- 初回から、本・読書メモ・読書ログ・設定をファイルに書き出し、復元できるようにする。手動の書き出し以降に追加・変更した記録は、そのファイルには含まれない。
- 初回はログイン画面で保存先の違いを説明し、「ゲストとして始める」を選べるようにする。ゲスト利用を選んだブラウザーでは次回からゲストの蔵書を直接開く。
- ゲストにもタイトル検索・ISBN検索・バーコード読み取りによる追加を提供する。検索語やISBNはサーバー経由でGoogle Booksへ送信され、蔵書・読書記録は端末内へ保存することを説明する。未ログインの検索には利用回数の制限を設ける。
- 引き継ぎ先に同じISBNの本があっても、自動統合・上書きはせず別の本として追加する。同じ引き継ぎの再試行による二重登録は防ぐ。
- アカウントへの引き継ぎ完了後も、元のゲストデータは明示的に削除するまで端末に残す。以降はクラウドと同期せず、ゲストへ戻ると端末に残った記録を表示する。この違いを画面で明示する。
- バックアップの復元は現在のゲストデータをファイルの内容で置き換える方式とする。復元前に置き換えを確認し、現在の記録を書き出せるようにする。ファイル全体の検証が成功してから反映し、失敗時は現在の記録を残す。アカウントの記録には触れない。

## 実装方式

- 保存先は`localStorage`の`yomi:guest-library:v1`。本・メモ・全読書ログ・設定を一つのバージョン付きJSONとして保存し、Web Locksでタブ間の更新を直列化する。保存前に全体を検証し、失敗時は書き換えない。Web Locksを利用できない環境ではゲスト保存を拒否し、ログイン利用を案内する。
- ゲスト蔵書全体はUTF-8で4MB、本1冊の記録は1MBまで。ブラウザー側の容量制限によって、これより早く保存に失敗する場合もエラーを表示する。表紙は画像本体ではなくURLを保存する。
- 引き継ぎは本ごとにメモ・ログ・完了印を同じD1 batchへ含める。完了印はアカウントごとに分離し、本の完全削除後も保持する。再試行は未完了の本だけを追加し、既に引き継いだ本は更新しない。
- アカウントのタイムゾーンが未設定ならゲスト設定を採用する。既に設定されていれば維持し、ログの論理読書日を引き継ぎ先の軸へ移す。日付表示と読書日の間隔は保持する。引き継いだログは負数の世代番号へ分離し、今後アカウントで記録する世代と衝突させない。
- 検索はD1の共有カウンターで接続元ごとに30回/分、アプリ全体で300回/分を制限する。ログイン利用者にも適用する。D1が利用できない場合は検索を実行しない。
- 利用モードの変更は画面の再読み込みを伴い、アカウントのデータをゲスト保存へ流さない。認証切れだけではゲストモードにしない。
- バックアップはバージョン・重複ID・ページ数・日付・設定などを検証してから、ゲストデータ全体を置き換える。アカウントへの自動送信はしない。

## 調査開始時の実装

- `src/components/SessionGuard.tsx` は未認証の場合にログイン画面へ遷移する。
- `src/server/middleware/auth.ts` は未認証のAPI呼び出しを拒否する。
- `src/server/routes/search.ts` の検索も認証を必要とする。
- `src/store/useLibraryStore.ts` の取得・更新はHTTP APIを使用する。読書ログは本一覧とは別に取得するため、本の配列の永続化だけでは足りない。
- 進捗更新時のログ補正やタイムゾーン変更時の読書日の扱いも、ゲスト用の保存経路で維持する必要がある。
- 設定内のタイムゾーン変更・アーカイブ復元も現在はログイン利用者向けの表示に含まれる。

主な変更範囲は、開始画面・認証ガード・蔵書ストアの保存処理・設定画面・検索の認証条件・引き継ぎ処理・バックアップ処理と、それらの検証。既存の読書日・星の計算を再利用し、保存先を変えても記録の意味を維持する。
